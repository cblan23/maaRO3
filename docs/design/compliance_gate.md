# RO3 自动化项目合规门

> 状态：**LIVE AUTOMATION BLOCKED／正式服实时自动化阻断**  
> 基准日期：2026-07-26（Asia/Shanghai）  
> 作用：工程范围控制与发布门禁，不是对任何主体提供法律意见，也不代替权利人书面许可或专业法律审查。

## 1. 结论先行

在取得适用于**具体地区、具体客户端、具体服务器和具体行为**的明确书面许可前，本仓库只能进入 `OFFLINE_RESEARCH` 模式：做资料整理、离线录像分析、合成画面测试、模板／状态机设计和不连接真实客户端的单元测试。

以下能力不得对官方客户端、官方测试服或正式服启用：

- 自动日常、自动任务、自动练级、自动打怪、自动吃药、自动拾取、自动回城、自动重连及循环挂机；
- 以截图／OCR／视觉识别结果驱动键鼠或触控输入，即使没有读写内存；
- 自动开启、维持或重启游戏内建辅助战斗；
- 多账号、多开调度、账号农场、打金、代练或无人值守收益循环；
- 自动摆摊、扫货、抢购、定价、跨服套利或任何交易自动化；
- PVP、GVG、公会战、排行榜、竞技、十人 RAID、百人 GVE 等竞争或团队机制玩法自动化；
- 修改客户端、注入、读写进程内存、反调试／反检测、规避反作弊；
- 抓包、协议模拟、私有接口调用、未经授权连接、逆向工程或利用漏洞。

这不是“降低风险后可以先做”的软建议，而是当前设计的硬阻断条件。

## 4. 默认允许运行的范围

### 4.1 无需连接官方客户端的离线研究

当前可继续：

- 阅读和归档公开官方资料，记录 URL、日期、地区、构建版本和证据等级；
- 分析项目成员有权使用的本地录像或截图，但不把受版权保护的完整素材随仓库再发布；
- 用合成 UI、手工绘制占位图或明确获准的素材开发 OCR、模板匹配和状态机；
- 对录制帧执行离线识别、时间线标注、误识率统计和回放测试；
- 编写不包含真实客户端连接、输入注入或协议实现的接口、配置 schema 和测试桩；
- 设计人工提示、清单和数据采集流程，由用户自行完成实际操作。

### 4.2 仍需额外确认的只读采集

自动截图、窗口枚举、OCR 叠加层和长时间录屏虽然不直接输入操作，也可能受测试协议、反作弊和素材使用条款约束。因此仓库默认不把它们接到官方客户端。需要真实客户端采样时，应先完成至少 G0～G2，并优先采用运营方明确允许的系统录屏方式和人工触发流程。

## 6. 门禁流程

### G0　来源与适用范围确认

必须同时完成：

1. 标明目标是国服、全球服、台港澳测试还是权利人内部环境。
2. 保存当日适用的通用协议、RO3 专项协议、测试规则和反外挂公告的 URL、版本和生效日期。
3. 识别平台方、游戏权利人、实际运营方和书面文件签发主体。
4. 处理协议冲突与产品命名异常；未澄清时按更严格范围阻断。

**失败条件**：专项协议缺失、页面不可访问、主体不明、不同地区材料混用或条款版本过期。

### G1　专项书面许可确认

许可文件必须明确写出，而不是由项目组推断：

- 产品全名、地区、服务器、客户端渠道和构建版本；
- 被许可主体、测试人员、账号／设备范围和有效期；
- 是否允许屏幕采集、OCR、窗口控制、模拟键鼠／触控、无人值守、循环执行和异常重连；
- 是否允许控制游戏内建辅助战斗；
- 允许测试的具体玩法，是否排除交易、PVP、GVG、排行榜、RAID 与多账号；
- 是否允许保存、共享、开源或发布代码、模板、日志、截图和视频；
- 反作弊白名单、频率限制、数据处理、保密、撤销和事故联系人；
- 签发人有权代表相关平台方和游戏权利人作出该授权。

国服至少需要能明确覆盖 Bilibili 平台侧和游戏权利人侧的文件；若文件只来自一方、只写“可测试”、只允许普通游玩或只允许使用内建辅助，则 G1 失败。客服未回复、公开招募测试、账号获得资格、官方人员观看演示、GitHub 开源或非商业使用，都不构成许可推定。

### G2　隔离测试环境确认

要求：

- 使用授权文件指定的测试服务器、专用账号、设备和时间窗；
- 禁止接触真实玩家经济、排名、竞技、公会战和正式服资产；
- 设置人工急停、最大动作数、最大运行时长和单账号速率上限；
- 日志不得记录账号密码、身份证信息、聊天内容或无关玩家个人信息；
- 运营方要求的反作弊白名单或测试标识必须已生效。

**失败条件**：只能在正式服验证、需用普通玩家账号、无法隔离经济／竞技影响，或反作弊状态不明确。

### G3　技术范围审查

只有授权行为可以映射到功能；授权没有提及的能力默认关闭。无论授权范围如何，本项目仍永久排除：客户端修改、进程注入、内存读写、反作弊规避、抓包、私有协议、漏洞利用和凭据自动化。

技术实现必须：

- `fail closed`：许可清单、环境指纹或有效期不匹配就拒绝启动；
- 只允许白名单任务、白名单界面和白名单动作；
- 每个动作保留可审计的触发原因、时间戳和授权条目 ID；
- UI 未识别、网络异常、角色死亡、弹出协议、出现其他玩家举报／GM 提示时立即停止；
- 不实现“随机化输入”“规避检测”“类人化逃避风控”等功能。

### G4　功能级风险审查

每个功能必须有独立记录：

- 功能名、业务目的、具体动作、循环上限和停止条件；
- 对账号、其他玩家、经济、排名和团队的影响；
- 对应书面许可的精确章节／附件；
- 测试证据与批准人；
- 是否允许分发，还是只允许内部验证。

不得以“框架整体获准”替代功能级映射。新增任务、切换服务器、变更输入方式或扩大循环次数都需重新过门。

### G5　发布门

内部测试授权不等于公开发布授权。公开二进制、脚本、模板、动作配置或使用说明前，必须另有明确覆盖分发／开源的书面文件，并完成安全和隐私审查。否则仓库发布物只能包含离线研究能力与模拟测试桩。

### G6　持续复核与撤销

出现以下任一事件立即回到 `BLOCKED`：

- 协议、反外挂公告、客户端渠道、运营主体或服务器改变；
- 授权到期、撤销、签发主体变化或适用账号变化；
- 客户端大版本更新、反作弊升级、功能从测试服迁移到正式服；
- 发现功能影响交易、排名、他人体验或超出动作／时长上限；
- 无法证明当前运行实例与授权环境匹配。

## 7. 运行模式设计

### `OFFLINE_RESEARCH`（默认且当前唯一可用）

- 不发现、启动、附加或控制官方客户端；
- 输入只能来自本地录像、截图目录或合成测试源；
- 输出只能是识别结果、标注、报告和模拟动作日志；
- 所有真实输入后端、窗口控制后端和循环调度后端在构建／配置层关闭。

### `AUTHORIZED_TEST`（预留、默认不可达）

只有 G0～G4 全部通过后才能由维护者显式启用。启动时至少校验：

- 授权 ID、有效期、地区、服务器、客户端哈希／版本；
- 测试账号和设备标识；
- 功能白名单、动作预算、时间预算；
- 急停通道和审计日志目录。

任一字段缺失、模糊或不匹配，立即拒绝运行。不得提供 `--force`、跳过校验或静默降级到真实输入的选项。

### 不设“普通正式服自动化”模式

除非未来出现明确覆盖正式服使用和公开分发的有效书面授权，并重新修订本文件，否则设计中不存在 `PRODUCTION_BOT`、`LIVE_FARM` 或同类运行模式。

## 9. 2026-08-25／27 必做复核

1. 下载前保存国服招募公告和当日 Bilibili 通用协议版本。
2. 安装前阅读并保存启动器、客户端、测试服全部专项协议和弹窗；不同意则不进入客户端。

## 10. 不作许可推断

以下说法均不能越过本门禁：

- “游戏自己有自动战斗，所以外部脚本也可以。”
- “只做图像识别和点击，不读内存，不算外挂。”
- “不收费／开源／自己用，所以不受协议限制。”
- “测试服是删档的，自动化不会造成损失。”
- “客服没有反对／群管理员看到了／其他玩家也在用。”
- “全球条款不适用于中国，所以国服没有限制。”
- “拿到测试资格，就等于拿到自动化测试授权。”
- “MAA 只是框架，具体任务由用户负责。”

当前唯一可靠的工程结论是：**没有覆盖目标行为的明确书面许可，就不连接真实客户端执行自动化。**
