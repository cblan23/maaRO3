# RO3 日常系统百科与首期自动化边界

> 基准日期：2026-07-28。本文专门回答“玩家在主线之外反复做什么、怎样进入、怎样判断完成、什么情况下必须停机”。它不是国服攻略，也不表示当前已经获准连接真实客户端发送输入。

## 0. 适用版本与结论

本文严格区分两个构建：

- `CN-A`：Bilibili 国服《仙境传说3》；已公告 2026-08-27 开始 PC 限量删档“重逢测试”，截至本文日期尚未开测。
- `TEST-B`：同项目台港澳 2026-06-25 至 07-02“启燃测试”；目前绝大多数系统和 UI 证据来自这里，只能作为国服采样假设。
- `PIONEER-A`：2025 先锋测试旧构建；只保留跨构建状态语义和负例，禁止混入 TEST-B／国服模板。

所有等级、次数、活力、时间、奖励、重置点和快捷键都是版本字段。国服首测前，最合理的首期形态不是自行实现打怪 AI，而是：

1. 读取每日面板、资源和奖励状态；
2. 编排游戏自身的寻路与辅助战斗；
3. 看护死亡、无目标、卡位、背包和掉线等边界；
4. 遇到消费、交易、竞争、选择题或未知页面立即交给玩家。

当前 Bilibili 通用协议把模拟操作、自动练级、自动吃药和自动任务列为未经许可第三方程序示例。因此真实客户端输入仍由 [合规门](../design/compliance_gate.md) 阻断；下文的“候选操作链”只用于研究、离线回放和未来书面授权测试。

## 1. 每项任务共用的状态合同

任何候选任务都不能写成“找到按钮就一直点”。最小事务应为：

```text
Discover entry
  → Read region/build/UI profile
  → Read preconditions and resource budget
  → Create one bounded intent
  → Perform at most one authorized input
  → Observe multiple fresh frames
  → Verify task-specific postcondition
  → Journal before/after values
  → Return to discovery, or stop on mismatch
```

通用完成判据必须至少包含一种业务变化，而不是“窗口消失”：

- 任务当前数增加或条目变为已完成；
- 活跃度增加且未超过预期；
- 资源、材料和产物按预期同时变化；
- 奖励按钮从可领变为已领；
- 挂机计时、击杀或掉落统计发生合理变化；
- 登录后连续多帧稳定进入角色世界。

通用安全停机条件：

- 未知页面、UI 布局或缩放与环境指纹不符；
- 付费货币、购买、抽取、精炼、扩容、交易或二次确认弹窗；
- PVP、MVP、GVG、排行榜、队拍或需要多人协作的机制场景；
- 角色疑似死亡、血量危险、药品耗尽或背包异常；
- 掉线、维护、更新、验证码、登录凭证或排队页面；
- 任务／寻路／战斗在观察窗内无进度；
- 实际资源扣除大于意图预算；
- 暂停恢复后无法重新发现当前入口和状态。

## 2. 主线、等级门与系统解锁

主线本身是一次性内容，不是首期高回报自动化目标，但它决定每日系统何时出现。`TEST-B` 快速开放节奏中看到的等级如下：

| 等级 | 旧测试开放项 | 可信边界 |
|---:|---|---|
| 10 | 一转 | 只代表启燃测试 |
| 30 | 二转、装备制作相关 | 只代表启燃测试 |
| 31 | 游戏内建辅助战斗 | 攻略称 `Z` 开关、右键设置技能 |
| 33 | 宠物 | 只代表启燃测试 |
| 34 | 生活职业、每日必做 | 画面与攻略交叉支持 |
| 36 | 五人本 | 本文不继续设计副本 |
| 约 37／预告 40 | 野外挂机 | 两处口径冲突，必须读取锁定原因 |

测试还采用首日 39、次日 45、第三日 49、第四日开放三转等压缩节奏，不能外推国服正式开放速度。来源：[Day1 完整攻略](https://www.bilibili.com/video/BV1YqTK6oEkk/)、[Day2 攻略](https://www.bilibili.com/video/BV1GqTK6oE4n/)。

| 字段 | 当前结论 |
|---|---|
| 构建／证据 | `TEST-B`；多段玩家实机显示右侧任务追踪和自动寻路，国服仅确认 PC 点击移动／走位设计 |
| 解锁与入口 | 右侧任务追踪中的主线、支线等条目；实际系统开放应读取“未解锁原因”，不能用等级常量猜 |
| 操作链 | 点击追踪 → 游戏内寻路 → 跨图／加载 → NPC 对话、交物、采集或战斗 → 当前目标更新 → 下一环或等级门 |
| 次数／资源／重置 | 主线通常一次性；可能消耗传送费、任务物、时间或触发战斗，公开资料没有统一资源表 |
| 完成判据 | 目标数字变化、任务名／阶段改变、原条目消失、奖励出现或明确等级门；页面关闭不算完成 |
| UI 证据 | Day1、Day2 和[完整启燃实机](https://www.bilibili.com/video/BV18H756KEhz/)持续显示任务追踪、寻路和跨场景流程 |
| 自动化风险 | 剧情选择、跳过、传送确认、NPC 遮挡、目标被抢、跨图失败、死亡、背包要求、组队召集 |
| 首期建议 | 只记录系统开放与当前目标；主线由玩家推进，必要时只监视寻路是否停止 |
| 国服待验证 | 寻路视觉标志、取消方式、人工移动是否打断、跨图后的继续条件、剧情选择和最终完成标志 |

## 3. 每日／周常面板、活跃度与奖励

旧测试每日页同时承担“任务目录、进度、前往入口、活跃度和活动日历”五种职责。页面会随等级增加条目，因此它应是每次运行的动态发现入口，而不是固定任务数组。

| 字段 | 当前结论 |
|---|---|
| 构建／证据 | `TEST-B`；[每日面板帧](../../research/evidence/video/day1-guide-bv1yqtk6oekk/frames/0392-daily-panel.png)与[扩展面板帧](../../research/evidence/video/day1-guide-bv1yqtk6oekk/frames/0466-daily-panel-expanded.png) |
| 解锁与入口 | 旧测试约 Lv34 开放“每日必做”；页面有“必做／周常”标签、任务列表、底部活跃箱和右侧限时活动 |
| 操作链 | 打开页面 → 逐页／滚动读取条目 → 记录锁定、进度、完成、前往、可领 → 选择一个独立子任务 → 返回后重新读取全页 |
| 次数／资源／重置 | 旧画面活跃箱阶段为 20／40／60／80／100；曾显示每日 05:00、周一 05:00 更新，均为易变快照 |
| 完成判据 | 子项进度达到目标或“已完成”；活跃值按预期增加；箱子从可领变为已领；三者必须分开记录 |
| UI 证据 | 初始／扩展面板可见各任务；另有 20 档活跃箱金色可领 → 过渡 → 绿色已领的 0.1 秒级连续序列 |
| 自动化风险 | 动态解锁、滚动列表、限时活动插入、红点不等于可安全领取、奖励选择箱、背包满、跨重置运行 |
| 首期建议 | 每日状态看板和本地提醒；活跃箱先只提示，未来授权测试也只能逐箱白名单领取 |
| 国服待验证 | 页面名称、开放等级、任务全集、排序、阈值、日／周重置点、跨日时已打开页面是否自动刷新 |

建议把页面快照记录为独立字段，而不是一个 `daily_done` 布尔值：

```text
task_name / task_kind / unlock_reason
current / target / active_points
entry_available / reward_available / claimed
server_reset_text / observed_at / region / build_id
```

## 4. 呆呆委托

玩家一手长文将其描述为专门配合游戏内自动流程设计的跑腿／打怪任务，并称不启用自动时部分步骤甚至难以完成。另一份玩家建议称一项日常会跑五个地方、来回约十趟。该数字是体验描述而非连续画面计数，只能证明流程可能很长、跨多个目标，不能证明每一环都会无人值守完成。来源：[测试体验 Part 2](https://forum.gamer.com.tw/C.php?bsn=81475&snA=82)、[启燃测试心得](https://forum.gamer.com.tw/Co.php?bsn=81475&sn=189)。

| 字段 | 当前结论 |
|---|---|
| 构建／证据 | `TEST-B`；每日面板有“完成呆呆发布的委托任务，获得大量经验”和“前往”入口，流程细节主要来自玩家一手体验 |
| 解锁与入口 | 每日必做 → 呆呆委托 → 前往；也可能直接导航到委托 NPC |
| 操作链 | 前往／NPC → 接取 → 游戏内寻路 → 对话、交互、采集或击杀 → 交付 → 下一环或每日完成 |
| 次数／资源／重置 | 每日环数未知；奖励可确认包含经验，但单环／整轮奖励、活跃值和重置均未可靠读取 |
| 完成判据 | 任务追踪的当前数或阶段改变；最终每日条目变完成；不能把“角色走到 NPC”当作完成 |
| UI 证据 | [每日面板 06:32](../../research/evidence/video/day1-guide-bv1yqtk6oekk/frames/0392-daily-panel.png)；尚无完整一轮高分辨率时间线 |
| 自动化风险 | 自动寻路中断、跨图、对话选择、任务物不足、目标被抢、临时战斗、背包要求、组队状态、任务 Bug |
| 安全停机 | 出现选择题／确认、60–90 秒无任务进度、寻路标志消失但未到达、死亡／掉线、进入多人或竞争场景 |
| 首期建议 | 读取当前环并监视游戏内寻路；不自动接下一环，不用坐标点击替代游戏寻路 |
| 国服待验证 | 每日环数、是否自动连续接环、各种任务类型比例、跨图恢复、最终完成标记、主动取消和重入点 |

## 5. 公会物资／公会商队

玩家一手资料称其核心是提交指定物资换经验，同时增加公会资金；Part 2 作者称测试期多数需求可在普通补给商店使用一般游戏币购买。另两名玩家却称商队会要求生活职业产物，因每日生活资源有上限而限制了职业选择。两者可能分别描述“多数项目”和“少数无法直接买的项目”，也可能来自不同日期／需求池；在拿到连续 7 天清单前必须保留冲突。无论哪种口径，“容易购买”都不能成为自动购买依据，因为提交和购买是不可逆经济动作。

新增 [Twitch 连续证据](../../research/evidence/video/twitch-vod-2805645541/manifest.json)已经覆盖一个正常单批：选中煤矿石 `6/6`、载货 `7/8` → “物品已提交”、`8/8` → 公会贡献／钱币提示 → 奖励覆盖层 → “装运商队 2/4”与新需求。新批次直接显示铁矿石 `0/6` 等不足行及求助／一键购买入口。另一条[二次剪辑中的三帧直接证据](../../research/evidence/video/test-b-long-review-bv1rrmw6qeom/manifest.json)补到“装运商队 `4/4`”，并在同一短片段展示载货量 `4/8` 时发车禁用、`5/8` 时黄色“发车”按钮启用。它们共同证明需求选择、满足／不足计数、提交反馈、满载奖励、批次刷新、第四批页面及本次发车入口边界确实存在，但没有提交后的背包数量、选择不足项后的失败／禁用状态、购买／求助结果或点击发车后的第四批终局。

| 字段 | 当前结论 |
|---|---|
| 构建／证据 | `TEST-B`；每日面板条目、玩家长文和 `7/8 → 8/8 → 奖励 → 2/4` 连续实机 |
| 解锁与入口 | 加入公会后，每日必做 → 公会商队／物资 → 前往；实际页面名称在不同资料中有“商队／物资”差异 |
| 操作链 | 打开需求列表 → 读取每项物品、数量、品质与库存 → 只标记可安全提交项 → 人工确认 → 提交 → 复查任务和库存 |
| 次数／资源／重置 | 连续单批样本为 `1/4 → 2/4`、载货 `7/8 → 8/8`；第四批短片段为 `4/8` 发车禁用 → `5/8` 发车可用；需求数量、随机池和中间刷新仍未知 |
| 完成判据 | 单项出现“物品已提交”；载货达 `8/8` 后奖励层与批次增加。第四批 `5/8` 只证明允许提前发车，不是已发车或全部完成；背包扣物、四批结束与每日完成仍须分开验证 |
| UI 证据 | [8 帧正常单批 Manifest](../../research/evidence/video/twitch-vod-2805645541/manifest.json)覆盖每日完成入口、需求满足、提交、满载、奖励和下一批；[3 帧第四批 Manifest](../../research/evidence/video/test-b-long-review-bv1rrmw6qeom/manifest.json)覆盖 `4/4` 与发车禁用／可用 |
| 自动化风险 | 提交稀有／锁定／养成材料、库存不足后跳转购买、货币消费、需求刷新、误入公会活动、权限不足 |
| 安全停机 | 任何购买入口、稀有度不在白名单、数量／品质 OCR 不确定、扣除预览与意图不符、弹出二次确认 |
| 首期建议 | 只读“今天需要什么、背包已有多少”；不自动购买；即使将来获授权，提交也逐项人工确认 |
| 国服待验证 | 精确入口、每天项数、需求池、背包扣除、不足／购买、发车确认与第四批终局、每日变化、锁定物是否可选、退出公会后的状态 |

[公会活动页](../../research/evidence/video/test-closeout-bv1ybny6feze/frames/0092-guild-activity-calendar.png)还显示领地争霸战、抢亲大作战、公会联赛、自然之神伊尔玛塔和狩猎挑战为不同的定时卡片。它们用于场景分类和停止，不属于公会物资事务，也不能从公会页误点进入。

## 7. 野外挂机、三阶段收益与内建辅助战斗

### 7.1 游戏自身提供什么

官方制作人采访确认游戏有辅助战斗，并称设计目标是手动收益较高，辅助收益约为手动的 70%–80%，用于练级、打怪或临时离开；这是产品功能说明，不是外部自动化许可。来源：[制作人采访](https://news.pchome.com.tw/game/gamer/20260129/index-76964660191804203104.html)。

旧测试攻略称 Lv31 解锁，`Z` 开关、鼠标右键配置技能。[设置帧](../../research/evidence/video/test-closeout-bv1ybny6feze/frames/0107-auto-battle-settings.png)能证明自动战斗窗按类别列出技能与等级。一名 [TEST-B 玩家](https://forum.gamer.com.tw/C.php?bsn=81475&snA=73)进一步报告：内挂只会施放六格热键栏中的技能，战斗中不能更换栏位，并怀疑猎人的辅助施放速度只有手动的一部分。后半部分是单一职业、单一玩家行为证据，必须逐职业复测，不能当作产品承诺。

### 7.3 三阶段不能硬编码

现有资料支持“至少三种收益状态”，但对第二、第三阶段的物品集合存在直接冲突：

| 阶段候选 | TEST-B 当前线索 | 转换条件线索 | 自动化所需字段 |
|---|---|---|---|
| 加倍／高倍挂机 | 大量经验、装备、卡片；旧测试每天 60 分钟、累计 180 分钟 | 玩家显式开启并消耗剩余分钟 | `boost_enabled`、`boost_remaining`、`boost_cap` |
| 低倍／一般、未疲劳 | `0秒/180分` 父帧直接出现继续变化的经验、齿轮／分解产物和物品通知；Day2 解说称仍有基础装备、材料和卡片，Day1 图文却称仅少量经验／基础材料且无装备卡 | 加倍结束后继续击杀；客户端没有在现有帧中显示“低倍”，玩家估计约 3000–5000 只后转疲劳但无清晰 UI 阈值 | `reward_tier`、`personal_kills`、`party_kills`、`card_eligible` |
| 疲劳 | Day2 解说称不再有卡片机会；另一名玩家称角色疲劳后“几乎没有任何收益”；其他奖励降到何种程度不一致 | 玩家一手文称按击杀数量而非时间；“几乎没有”不能解释为零收益 | `fatigue_state`、`fatigue_reason`、`reward_restrictions` |

高倍本身现有三态直接证据：[可开启](../../research/evidence/video/twitch-vod-2805739995/frames/5895.00-farming-boost-available-clean.jpg)、[运行倒计时](../../research/evidence/video/twitch-vod-2804892798/manifest.json)、[稳定耗尽与同步奖励通知](../../research/evidence/video/twitch-vod-2804807809/manifest.json)。耗尽页的 24 秒连续窗口中，奖励通知新增经验、齿轮和`连帽披肩 X1`且背景伤害持续，足以排除“归零即停战／必然完全零收益”。这些样本显著提高固定场景内的状态识别把握，但不同账号之间不能伪装成连续跨零，客户端也未把耗尽后的活动状态命名为“低倍”或“疲劳”。剩余冲突来源是：

- [Day1 图文版](https://home.gamer.com.tw/artwork.php?sn=6355828)把“加倍／一般”简化为两类，称一般挂机无装备和卡片。
- [Day2 录像 04:02–04:45](https://www.bilibili.com/video/BV1GqTK6oE4n/)讲解加倍结束后还有低倍、再进入疲劳，并称低倍仍能刷卡、疲劳后不能。
- [测试体验 Part 2](https://forum.gamer.com.tw/C.php?bsn=81475&snA=82)称疲劳按击杀只数计算；策略上加倍阶段打易怪提高击杀量，疲劳前打难怪提高单只收益。

因此首测必须直接 OCR 国服规则页，并在同一怪物、同一队伍下记录阶段切换前后计时、个人／队友击杀和掉落。未采到边界前，不得根据攻略主动切换目标。

### 7.4 连续挂机视频补充出的 UI 行为

[《6 分钟挂出 2 张卡》](https://www.bilibili.com/video/BV1FkKd6CEYL/)是 2026-06-30 的 TEST-B 连续实机，约 5:15。它能支持以下时间线：

### 7.5 挂机健康检查

另一段 2026-07-26 发布的 [14 秒 TEST-B 片段](https://www.bilibili.com/video/BV1rg376UE6k/)展示角色在狭窄走廊边缘持续动作、出现伤害数字，但约 13 秒没有有效位移进展；作者标题称近战自动挂机被地形卡住反复左右。它是 `AutoOnBlockedCandidate`，不是完整异常流程：画面未清晰证明 AutoOn／选中目标，也没拍到系统自行恢复或玩家停止。因此可用于验证“动作仍在发生但业务无进展”的识别思路，不能提供固定报警秒数或恢复动作。

不能用单帧“没有目标”判卡死。推荐只读观察窗至少组合以下信号：

- 目标名称／血量周期性出现并归零；
- 角色位置、朝向或攻击动作变化；
- 技能冷却、伤害数字、击杀数、Base／Job 或掉落日志变化；
- 自动战斗状态标志在多帧中稳定；
- 当前地图和选中目标仍与玩家配置一致；
- HP／SP、消耗品、背包状态未进入危险区；
- 加倍分钟和奖励阶段按预期变化。

候选状态至少分开：

```text
AutoOff / AutoStarting / AutoOnMoving / AutoOnFighting
AutoOnNoTarget / AutoOnBlocked / AutoStoppedByUser
AutoStoppedByDeath / AutoStoppedByTransfer / AutoStoppedByDisconnect
BoostEnded / FatigueReached / UnknownRewardTier
```

任何外部恢复动作都默认禁用。检测到持续无进度时保存前后帧并提醒玩家，不盲按 `Z`，因为 toggle 在状态未知时可能反而重新开启战斗。

| 完成判据 | 层标记通关、下一层解锁、奖励可领／已领；失败页面和无消耗退出必须另建状态 |
| UI 证据 | [每日面板](../../research/evidence/video/day1-guide-bv1yqtk6oekk/frames/0392-daily-panel.png)证明入口；[主战／三支援](../../research/evidence/video/pet-system-bv14gtk6lelc/frames/0510-pet-main-support-slots.png)、[助战五槽](../../research/evidence/video/test-closeout-bv1ybny6feze/frames/0062-pet-support-five-slots.png)和[孵化房](../../research/evidence/video/pet-system-bv14gtk6lelc/frames/0210-pet-incubation-level-probability.png)证明编队／养成字段；没有完整塔层／结算证据帧 |
| 自动化风险 | 误抽宠、误升阶／分解、改变主战技能、自动战斗无法处理 Boss 区域、失败消耗、进入付费页面 |
| 首期建议 | 只读编队、层数和可领奖；不抽取、不养成、不自动进塔战斗 |
| 国服待验证 | 主战／支援／助战槽位及等级门槛、属性和技能生效、孵化字段、塔层与重置、挑战资源、失败结果、扫荡和奖励领取 |

## 10. 背包、仓库与药品

这三项是挂机能否安全运行的前置依赖。公开资料已补到正常容量和快捷用药配置，但高风险终态仍不足，不能借用 RO Origin、ROX 或《守护永恒的爱》的规则补空白。

| 子系统 | 已经能证明 | 仍不能证明 | 首期处理 |
|---|---|---|---|
| 背包 | 已保存 `0/300` 空包、`36/300` 正常包和 HUD 入口 | 接近满／真正满、扩容变化、负重、满包弹窗、掉落去向、临时包／邮件 | 可直接研究容量 OCR；真正满包仍立即停机 |
| 仓库 | 暂无同项目启燃测试可靠完整样本 | 卡普拉仓库入口、账号／角色共享、费用、容量、锁定和批量存取 | 不设计自动存取；列为首测必采 |
| 药品 | 快捷用药页有“HP 低于 70% 自动使用”、阈值、槽位；数量 `36 → 35`，配置缺药有明确反馈 | 自动触发仍需排除手动键；`1 → 0`、SP、冷却、补槽、购买和死亡前行为 | 玩家预设，脚本只看护数量／血量；不自动制作、购买或补槽 |

玩家长文所称“最后一两天接近满载”特指卡片与灵魂残响分类背包，不是通用 `x/300` 物品栏；帖子原图没有容量读数、满包提示或下一掉落去向。国服采样必须分别记录普通物品、卡片、灵魂残响等分类容量，不能用一个总容量阈值替代所有分类。

药品制作是“生活资源事务”，药品使用是“战斗安全事务”，两者不能合并。`36 → 35` 与启用态相互印证，但录像没有键盘输入可视化，所以仍由玩家预先配置药品与阈值；监视器只在数量不足或血量异常时停止，而不是自行购物补货。

国服首测必须自然采集：容量页、接近满、真正满包、拾取后去向、药品 `1 → 0` 和仓库完整往返。不得为了数据故意丢弃稀有物或购买扩容。

## 11. 死亡与复活

现有玩家自身死亡帧仍只来自副本，包含个人等待、队友复活邀请、团灭和再战。另有[生存竞争模式队友复活弹窗](../../research/evidence/video/test-b-long-review-bv1rrmw6qeom/frames/0544.90-survival-teammate-revive-prompt.png)：存活玩家在救护车交互中看到身份牌样式图标和“复活”按钮，但没有点击或结果。两类画面都不能外推野外玩家自身死亡，因为按钮、费用、惩罚、落点和自动战斗恢复可能完全不同。

| 字段 | 当前结论 |
|---|---|
| 构建／证据 | `TEST-B` 副本自身死亡与生存模式队友复活提示有证据；开放世界玩家自身死亡无可靠同项目样本 |
| 入口／触发 | 野外触发条件显然是 HP 归零，但公开资料没有复活页面与费用画面 |
| 完成判据 | 首期没有自动复活事务；只要求多帧确认“疑似死亡”并停止所有输入 |
| UI 候选 | HP 归零、技能栏消失／禁用、画面变暗、死亡／复活文本或倒计时；必须与加载、掉线区分 |
| 自动化风险 | 错选付费／道具复活、回城惩罚、原地继续战斗、共享团队复活数、死亡循环、误判黑屏 |
| 首期建议 | `SuspectedDead → SafetyStop → 保存证据 → 通知人工`；不点任何复活选项 |
| 国服待验证 | 野外死亡页、选项、费用、惩罚、超时默认项、复活落点、保护时间、`Z` 状态和掉落损失 |

首测只在自然死亡发生时保留前 30 秒、后 60 秒；不应为采样故意送死或影响队友。

## 12. 启动、登录、排队、掉线与重连

截至基准日，没有找到能确认属于同项目、同次启燃测试的可靠排队／掉线／重连录像。这里必须保持“无公开证据”，而不是制作一套想象中的按钮模板。

需要分别采集的场景：

```text
LauncherUpdate / LauncherReady / Announcement
Login / ServerList / Queue / CharacterSelect / Loading
OpenWorldStable / DisconnectPopup / Reconnecting
ReconnectFailed / Maintenance / ClientCrashed / UnknownConnection
```

## 14. 奖励领取与重置的统一规则

奖励来源至少包括活跃阶段箱、日常条目、图鉴阶段、精灵之塔和活动／邮件；它们不能共用一个“领取全部”动作。

推荐每个奖励记录：

```text
source / reward_id / reward_preview
claimable / selection_required / inventory_required
before_inventory / after_inventory
before_state / after_state
reset_text / expires_at / evidence_frame
```

安全领取必须满足：奖励来源白名单、无需选择、不消费货币、背包状态已知、预览与识别一致。领取后至少验证按钮状态和库存／弹窗中的一种真实变化。出现自选箱、二次确认、过期转换、背包满或付费补领时交给人工。

重置时间以服务器页面原文为准。TEST-B 曾见每日 05:00、周一 05:00，但测试内容被压缩开放，国服不得沿用为常量。跨重置运行时应关闭旧快照、重新打开页面并生成新一日记录，不能继续执行前一天的意图队列。

## 16. 国服复验优先级

1. 登录、公告、服务器、排队、角色选择、加载和掉线全链路；
2. 每日页在不同等级的完整条目、活跃值和日／周重置；
3. 呆呆委托一整轮及每种中断；
4. 挂机规则高清原文、同账号高倍跨零、客户端低倍标签／掉率 → 疲劳连续边界；
5. 一次人工启动／停止游戏内辅助战斗，以及 `Z` 在传送、死亡、掉线后的状态；
6. 接近满／真正满包掉落去向、药品 `1 → 0` 和野外死亡；
7. 公会物资不足／购买分支、背包扣除和已知 `5/8` 发车可用之后的确认／终局，但不为采样购买或消耗稀有材料；
8. 生活 `80/100 → 100/100`、节点被抢／消失、活力恢复与一次制作前后；
9. 图鉴阶段奖励、组队归属、疲劳后计数；
10. 宠物塔层数、失败、奖励和重置，只读抽取／养成页面。

在以上样本缺失时，可靠的交付仍是“状态看板、提醒、审计日志和人工接管”，而不是靠旧测试坐标拼出无人值守脚本。
