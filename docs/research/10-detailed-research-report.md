## 1. 执行结论

本轮重新收集后，三个最优先场景已经不再处于“只有入口和口述”的低把握阶段。在限定前提、固定 TEST-B 画面和不考虑国服改版时，做出场景内全自动原型的工程把握为：

1. 已打开每日页的面板识别＋活跃箱领取：**96%**；
2. 已在目标地图、由玩家预配技能／药品的高倍挂机托管：**91%**；
3. 已在连续可见矿点区域的五次生活采集＋完成复核：**90%**。

这些不是线上实测成功率，而是“正常链证据、业务后置条件、状态变体和歧义是否已被公开资料覆盖”的工程置信度。若把“全自动”扩大为从启动器登录、任意地图导航、异常恢复、满包处理、野外复活和连接恢复都无人值守，三项当前分别评为 **72%／65%／62%**。本快照只各上调 2 个百分点：新增 TEST-B 正常进入录像关闭了启动器就绪、公告就绪、服务器入口与角色页的页面存在性缺口；它没有账号认证、排队／维护或可见输入事件，国服登录链和开放世界异常后的状态保留也仍未关闭，不能因为“页面能认”就大幅抬高。新补的 PIONEER-A 十人本队友复活链只增加旧副本反例，并显示接受后可见次数从 2 降到 1；它强化人工资源门，不提高任何一项国服无人值守评分。最新制作材料不足链增强了生活失败分类，却不覆盖采集节点、满包或成功制作，因此也不抬高第三项广义无人值守分数。

本轮真正改变判断的直接证据有：

- 活跃箱金色可领 → 短暂过渡 → 绿色已领；
- 公会商队 `7/8 → 8/8 → 提交反馈 → 奖励 → 2/4`，以及第四批 `4/8` 发车禁用 → `5/8` 黄色发车可用；
- 五次采矿严格资源变化，随后每日页 `100/100 已完成`；
- TEST-B 绿色药水 `锁定 → 1000 道具解锁确认 → 配方解锁 → 制作 → 道具不足`，并证明金色制作按钮不等于材料充足；
- 高倍可开启、运行倒计时、`0秒/180分` 稳定耗尽，以及耗尽页保持时经验、齿轮和`连帽披肩 X1`通知继续变化；
- 背包 `0/300` 与 `36/300` 正常容量基准；
- 快捷用药“HP 低于 70% 自动使用”、数量 `36 → 35`、配置缺药反馈；
- TEST-B 自然断线的重连中 → 双按钮重试 → 再次重连 → 要求重新登录 → 标题／公告／加载 → 回到世界；
- TEST-B 同一正常会话的启动器 Start Game → 公告就绪 → S1-01 服务器入口 → 最近角色／新建空位 → 95% 加载 → 开放世界页面链；
- TEST-B 自订 UI 布局编辑器直接显示 HUD 控制框可拖移及恢复预设入口，进一步否定固定绝对坐标前提；
- PIONEER-A 英文连接失败双按钮与角色选择页，严格隔离作跨构建语义样本；
- PIONEER-A 模拟对抗赛两轮 `死亡倒计时 → 复活点等待 → 0 秒 → HUD 恢复`，严格隔离作竞技死亡状态机与开放世界负例；
- PIONEER-A 英文攻城第一视角补出 `自动传送 10→0 → 独立复活等待 22→0 → HUD 恢复`双阶段回场链，并保存 `10／0` 自动传送与 `20／1` 复活等待四张裁图；
- PIONEER-A 印尼语十人本补出 `存活/次数2 → 幽灵/SOS → 队友邀请 → 接受 → HUD 恢复 → 成功提示/次数1`，保存六帧与五张裁图；资源可见减少反而证明自动接受必须保持人工门；
- GSTAR-2024 韩文 Boss 演示补出 `AliveHud → 原地复活覆盖层 → 覆盖层持续 → RevivedHud` 四帧边界；这是比 PIONEER-A 更早的副本自身复活语义，只作隔离负例，不能替代 TEST-B／国服野外复活；
- TEST-B 十人本持续个人死亡等待，新增父帧及 `dungeon_dead_wait` 裁图；另纠正“加班剩余时间”直播叠层被误读为游戏“加倍时间”的候选；
- TEST-B 生存竞争模式救护车“复活已死亡队友”弹窗，保存父帧与裁图，但严格作为竞技队友交互和野外自身复活负例；
- 背包容量正常样本扩展到 `56/300`、`62/300`、`110/300`，但最高仍只有 36.7%，不算接近满；
- 同一商城商品选中／可买 → 已售罄，以及衣橱普通／选中／已装备／锁定变体。
- TEST-B 精灵之塔同页普通未通关／黄色选中未通关／绿色已通关，以及里程碑奖励橙色可领 → 绿色已领；第 30 层另有“宠物蛋 ×3”到账提示作第二信号。

旧报告里的两项结论必须明确作废：公会物资并非“只有入口”；生活任务也不是 `4/5 → 5/5`，真实 TEST-B UI 按消耗活力显示 `100/100`。

## 6. 三个优先场景的分层把握

### 6.1 评分口径

三个数字必须分开：

- `TEST-B 窄流程`：父场景已经打开／角色已经到位，固定布局，只完成现有直接证据覆盖的事务；
- `CN-A 可交付预测`：国服开测后取得 2–3 个干净会话、完成字体／布局重标定，再交付同样窄流程；
- `广义无人值守`：从启动器或任意稳定世界开始，自动导航，并能处理满包、死亡和掉线等异常。

| 优先场景 | TEST-B 窄流程 | 国服复采后可交付预测 | 当前广义无人值守 | 主要限制 |
|---|---:|---:|---:|---|
| 每日面板识别＋活跃箱领取 | **96%** | **91%** | **72%** | 国服布局、打开入口、选择箱／满包、认证／排队与输入来源 |
| 目标地图高倍挂机＋内建补药托管 | **91%** | **85%** | **65%** | 真满包、药尽、低倍／疲劳、野外死亡、开放世界恢复状态 |
| 连续可见节点的生活五次采集 | **90%** | **83%** | **62%** | 自动找节点、被抢／消失、满包、跨图和连接状态保留 |

“国服复采后”是条件预测，不是现在已有的通过率。国服 UI 若大改或功能移除，对应分数应立即下降并回到 `needs_recheck`。

### 6.2 场景一：每日面板＋活跃箱

最小可交付范围：

```text
DailyPanelOpen
→ 读取条目、进度、已完成、锁定和活跃值
→ 只选择白名单、无需选择、无需消费的可领箱
→ 最多一次输入
→ 等待绿色已领或明确失败
→ 保存前后帧和日报
```

该场景把握最高，因为可领、过渡、已领已有连续画面，完成判据不依赖固定延时。广义分数下降来自登录、入口、滚动列表、跨日刷新和奖励选择分支，而不是领取本身。

### 6.3 场景二：目标地图高倍挂机托管

最小可交付范围：

```text
OpenWorldStable + target map + player preset skills/potions
→ 读取高倍状态
→ 授权后启动游戏内高倍／辅助战斗
→ 观察目标、伤害、击杀、位置、HP、药量、容量和倒计时
→ 高倍耗尽或任何未知危险时停止并通知
```

新增倒计时、用药和连接分类证据使正常托管已接近可做。不能宣称 8 小时无人值守，因为真正满包、`1 → 0`、野外死亡仍无恢复链，连接链也缺少输入来源和开放世界 Auto／任务状态保留。

### 6.4 场景三：五次生活采集

最小可交付范围：

```text
LifeGatheringAreaStable + five known visible/reachable nodes
→ 每个节点单独建立事务
→ 等待 4.5 秒进度完成
→ 验证拾取、活力 -20、熟练 +220
→ 总预算达到 100 后返回每日页
→ 验证 100/100 已完成
```

资源等差序列和最终完成态都直接存在，因此固定节点区把握高。任意地图自动寻矿仍低，因为节点被抢、遮挡、消失、路线和满包都没有样本。

## 7. 自动化设计边界

### 7.1 技术上应该复用游戏内能力

RO3 自身已经提供任务寻路、辅助战斗、目标选择和快捷低血量用药。外部系统的价值是：

- 读取玩家意图和预算；
- 检查设置是否完整；
- 观察业务进度；
- 在高倍耗尽、无目标、卡位、低血量、药少、容量危险或未知页面时停机；
- 保存证据并通知玩家。

不应再写一套技能循环、寻路算法或购物补药逻辑。

### 7.2 每个动作必须是有界事务

```text
Intent
→ Authorization + policy check
→ Build / DPI / UI profile check
→ Scene + resource precondition
→ Exactly one bounded input
→ Observe fresh frames
→ Verify business postcondition
→ Commit journal
→ Otherwise SafetyStop + evidence
```

未知状态不盲点，toggle 不盲按，失败不无限重试，暂停恢复不继续旧点击栈。

### 7.3 合规与技术把握分开

Bilibili 通用协议目前把模拟操作、自动练级／任务等列为未经许可第三方程序风险。上面的百分比只表示技术证据成熟度，不表示外部输入已获许可。真实客户端输入仍需要专项书面授权，并通过[合规门](../design/compliance_gate.md)。

| 公会剩余分支 | 不足／购买入口（不执行）、背包扣除、已知 `5/8` 发车可用后的人工点击、确认／成功／失败、第四批终局、每日变化 |
| 呆呆整轮 | 每日入口 → 接取 → 至少两类子目标 → 最后一环 → 交付 → 完成／活跃变化 |

采样不得为制造边界故意送死、丢弃稀有物、购买扩容或影响其他玩家；只记录自然出现的异常。

## 12. 最终判断

资料重新收集已经把三项正常流程推进到“可做限定场景全自动原型”的水平，而不是仍停留在只读提醒：每日面板／活跃箱 96%，目标地图高倍托管 91%，固定矿点五次采集 90%。新 TEST-B 录像又补到启动器、公告、服务器、角色、加载与世界的正常页面链，使三项广义无人值守评估谨慎升至 72%／65%／62%；这只反映页面分类更完整，不表示账号认证、点击或异常恢复已经可自动化。这三项最适合在国服开测后优先做同 build 复采和隔离验证。

但不能把这三个数字包装成任意状态下的零接管脚本。真正满包、药尽、低倍／疲劳、野外复活，以及连接中的账号认证、排队／维护、输入来源与异常后的状态保留仍会决定长时间无人值守的上限。正确的交付顺序是：先完成场景内有界事务，再用国服自然异常样本逐项扩大父状态；任何未知页面继续 fail closed。
