# 2026 年 8 月国服“重逢测试”采样手册

> 目标：把公开视频推断转成可重复、可版本化的国服证据。  
> 当前测试日期：2026-08-27；资格公布与预下载：2026-08-25 12:00。  
> 原则：由测试者人工操作。没有通过合规门时，不允许工具向客户端发送键鼠输入，也不自动附加客户端长时间采集。

## 1. 完成定义

首轮采样不以“把所有玩法打完”为目标，而以回答下面问题为完成：

1. 国服客户端能否被 Win32 Controller 稳定截图；
2. 客户端窗口、DPI、分辨率、UI 缩放和操作模式如何影响画面；
3. 登录、城镇、菜单、任务、日常、野外、战斗和异常能否被可靠区分；
4. 每个首期候选页面有哪些入口、前置、进行态、成功态和失败态；
5. 哪些旧测试结论已改变；
6. 专项协议是否允许任何真实客户端采集／自动化；
7. 是否具备足够样本进入离线识别开发。

未达到这些条件前，不冻结坐标、模板、等级、次数和任务路由。

## 2. G0：安装前合规采样

2026-08-25 预下载开放后，先保存和审阅：

- 国服招募公告及 FAQ；
- 当日《哔哩哔哩游戏中心用户协议》；
- 启动器协议、测试协议、RO3 专项 EULA；
- 隐私政策、反外挂／反作弊规则、社区规范；
- 录屏、直播、截图、保密和素材发布限制；
- 客户端内首次启动弹窗与版本公告；
- 运营主体、权利人、渠道和客服电话／工单入口。

全文检索并人工阅读这些词：`外挂`、`辅助`、`脚本`、`宏`、`自动`、`模拟操作`、`第三方软件`、`录屏`、`直播`、`保密`、`采集`、`反作弊`、`封禁`、`测试数据`。

如果协议禁止截图／录屏或测试保密，则停止公开画面采样，只记录不含受限内容的环境元数据。测试资格不等于自动化授权。

## 3. 采样机器与工具准备

### 3.1 建议准备

- Windows 11 主测试机；
- 至少 40 GB 独立临时空间；
- 系统录屏／截图工具，须符合测试规则；
- `ffprobe`／`ffmpeg` 或等价工具，用于离线确认帧率和抽帧；
- 本仓库的窗口枚举、Manifest 和校验工具；
- NTP 同步的系统时间；
- 一份人工操作日志模板；
- 随时可用的录屏暂停和隐私遮挡快捷键。

不准备：连点器、鼠标宏、键盘宏、注入器、抓包器、协议代理、多开同步器或反检测工具。

### 3.2 原始资料目录

原始录屏放在 Git 忽略的目录：

```text
research/raw/cn_reunion/<build_id>/<session_id>/
  environment.json
  operator_log.md
  recording-001.mkv
  screenshots/
  agreements/
```

提交仓库的只应是最少关键帧、脱敏后的环境记录、Manifest 和转述笔记。

### 3.3 会话命名

```text
CN-BILI-<build_id>-<YYYYMMDD-HHMM>-<purpose>-<operator>
```

示例：

```text
CN-BILI-0.1.23.456-20260827-1005-first-login-DORIA
```

如果客户端没有公开 build ID，记录启动器版本、主 EXE SHA-256、资源版本文本和公告日期，生成临时指纹。

## 4. 环境指纹

每次录屏前填写 [窗口配置样例](../../config/window_profile.example.json)，至少记录：

| 类别 | 字段 |
|---|---|
| 客户端 | 启动器版本、游戏 build、渠道、语言、进程名、EXE 哈希 |
| 窗口 | 标题、类名、窗口矩形、客户区矩形、最小／最大尺寸、焦点状态 |
| 显示 | 显示器分辨率、缩放、DPI、刷新率、HDR、主副屏 |
| 游戏 | 窗口／无边框／全屏、渲染分辨率、画质、UI 缩放、操作模式 |
| 截图 | 方式、输出尺寸、黑屏／透明／遮挡、前后台行为、色彩空间 |
| 账号 | 只记测试账号别名、角色职业／等级；不记录密码和实名信息 |

任何关键帧如果缺少环境指纹，只能用于人眼参考，不能进入回放测试基准。

## 5. Win32 截图方式标定

在不向客户端输入的前提下，由测试者手动把游戏停在同一静态城镇画面，依次评估：

| 候选方式 | 前台完整 | 后台完整 | 最小化 | 遮挡影响 | 动画撕裂 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| `PrintWindow` | 待测 | 待测 | 待测 | 待测 | 待测 | 未标定 |
| `ScreenCapture` | 待测 | 待测 | 不期望 | 可能有 | 待测 | 未标定 |
| `DXGI_DesktopDup` | 待测 | 待测 | 不期望 | 待测 | 待测 | 未标定 |

每种方式至少采 30 秒、固定 2 FPS 的人工触发样本，检查：

- 是否全黑、冻结或只截到边框；
- 鼠标是否出现在图中；
- 弹窗、视频、粒子和小地图是否完整；
- 切到后台后是否继续更新；
- Windows 缩放是否导致客户区偏移；
- 多显示器坐标是否为负；
- 客户区尺寸是否与输出帧一致。

当前 `assets/interface.json` 使用故意不匹配的窗口占位符。只有标定完成且合规审查允许后，才提交真实正则；不能先用 `.*` 匹配所有桌面窗口。

## 6. 画面变量矩阵

不要求一台机器穷举所有组合。优先覆盖用户最可能使用的组合，并为每组保存主页、菜单、日常和战斗各一帧。

| 变量 | 最低覆盖 |
|---|---|
| 客户区短边 | 720、900、1080（如果客户端支持） |
| Windows 缩放 | 100%、125%、150% 中至少两种 |
| 显示模式 | 窗口、无边框；独占全屏如存在再测 |
| UI 缩放 | 最小、默认、最大 |
| 操作模式 | 经典、现代；行动模式如开放则仅记录 |
| 语言 | 简体中文；其他语言只作扩展 |
| 画质 | 最低和推荐，观察特效／字体变化 |
| 色弱／辅助选项 | 如存在，记录是否改变机制颜色 |

矩阵的目的不是支持任意布局，而是决定首版只支持哪个“标准环境档案”。

## 7. 首次启动会话

### 7.1 启动链全程录像

人工从桌面开始，记录：

1. 启动器未登录；
2. Bilibili 登录／扫码／账号选择；
3. 更新检查、下载、校验；
4. 开始游戏按钮；
5. 反作弊启动过程；
6. 协议、公告、隐私和权限弹窗；
7. 服务器选择、排队、维护／爆满；
8. 角色列表、创建角色；
9. 进入游戏加载；
10. 首个可操作画面。

为每个节点记录可见文本、按钮、是否模态、关闭方式、加载持续时间和前后画面。登录凭据、二维码、手机号、UID、实名信息必须从提交证据中移除。

### 7.2 操作模式选择

对每个可选模式采：

- 未选中；
- 鼠标悬停；
- 选中；
- 说明文本；
- 确认前；
- 确认后首个 HUD；
- 设置中重新切换入口；
- 键位设置全页。

由测试者人工验证点地、WASD、锁敌、交互、镜头、自动战斗和快捷栏；在日志中记录，不由脚本试键。

## 8. UI 布局标定会话

### 8.1 设置页

逐标签展开并截图：画面、声音、操作、界面、快捷键、社交、隐私和其他。重点记录：

- UI 缩放的最小／最大／步长／默认值；
- 窗口能否拖动和缩放；
- 是否有恢复默认布局；
- 聊天、小地图、队伍、任务追踪能否分别隐藏；
- 字体大小、透明度、色弱模式；
- 自动战斗设置和技能选择；
- 按键冲突提示与可重绑范围。

### 8.2 布局变化样本

选择一个不会影响账号收益的普通菜单，人工完成：

1. 默认位置／默认大小；
2. 拖到左上、中央、右下；
3. 最小和最大尺寸；
4. UI 缩放最小／默认／最大；
5. 重启客户端后检查是否持久化；
6. 使用“恢复默认”后检查。

每步记录前后帧。由此决定识别用“相对窗口锚点”还是要求标准布局。

## 9. 基础场景字典采样

每个场景至少取 10 个相隔 500 ms 以上的帧，包含轻微动画差异：

| 场景族 | 必采状态 |
|---|---|
| Safety | 协议、付费、交易确认、验证码、GM／举报、敏感弹窗 |
| Connection | 启动、更新、登录、排队、加载、断线、重连、维护 |
| Character | 角色选择、创建、删除确认、职业预览 |
| Home | 城镇静止、城镇移动、NPC 密集、菜单展开／收起 |
| Menu | 角色、技能、背包、宠物、活动、设置 |
| Dialogue | 普通对话、选择题、剧情、接取／交付、跳过确认 |
| OpenWorld | 地图、传送、寻路中、到达、跨图加载 |
| Combat | 手动战斗、游戏内辅助战斗、无目标、Boss、低血量 |
| Party | 未组队、队员不足、完整队伍、成员离线／死亡 |
| Daily | 初始、滚动后、任务完成、箱可领／已领 |
| Instance | 入口、匹配、确认、战斗、失败、结算、退出 |
| Unknown | 遮挡、动画过渡、网络卡顿、未见过页面 |

`Unknown` 不是垃圾类。首期必须有足够未知帧来验证系统会停止，而不是强行把它归到最相似页面。

## 10. 日常面板采样协议

### 10.1 每次升级后重复

每日内容可能随等级增加。每次系统开放或等级提升后，人工执行：

1. 打开每日／活动页；
2. 截顶部标题和标签；
3. 从最上滚到最下，重叠 20% 录制；
4. 记录每条名称、说明、进度、活跃度、前往按钮；
5. 记录底部箱阈值和状态；
6. 展开周常、限时、日历；
7. 关闭并重开，检查排序与滚动位置；
8. 跨 05:00 前后或官方重置点时单独记录。

### 10.2 每个任务的状态组

| 状态 | 最低样本 |
|---|---:|
| 未解锁／锁定原因 | 3 帧 |
| 已解锁、进度 0 | 3 帧 |
| 部分进度 | 3 帧 |
| 已完成、未领 | 3 帧 |
| 已领取 | 3 帧 |
| 当日次数耗尽 | 3 帧 |
| 背包满／队伍不满足等阻断 | 能安全遇到时采 |

不要为了制造异常而浪费稀有资源、故意死亡或影响其他玩家。

## 11. 委托与任务导航采样

由人工完成一整轮，操作日志精确记录点击与时间：

```text
每日页前往
→ NPC／任务页
→ 接取
→ 寻路开始
→ 跨图／到达
→ 对话／采集／战斗
→ 交付
→ 下一环或完成
```

每个箭头前后取一组帧。重点观察：

- 寻路中图标／文本；
- 人工移动是否会打断；
- 战斗是否自动开启；
- 任务追踪如何更新；
- 目标被他人击杀、NPC 遮挡或距离过远；
- 等级／背包／队伍／时间门槛；
- 最后一环与普通环的差异。

## 12. 野外挂机与自动战斗采样

### 12.1 配置页

在不开始收益循环前，先录：

- 地图／等级区间下拉所有选项；
- 魔物列表、选中／未选中／不可选；
- 普通与加倍模式；
- 规则说明高清截图；
- 当前分钟、累计上限、今日击杀、疲劳；
- 加倍、低倍／一般、疲劳三种状态各自的名称、图标、规则原文与掉落限制；
- 高倍归零后不要立即退出：在同一怪物／队伍下保留低倍稳定态与疲劳前后掉落对照；玩家口述的“几乎没有收益”不能替代客户端状态；
- 组队说明；
- 开始按钮禁用的所有已知原因。

自动技能页必须额外录制：全部热键槽、设置页对应项、启用／禁用标志、技能等级、战斗中尝试换格时的原生提示。玩家分别用至少一个普攻职业、施法职业和猎人手动运行 60 秒、辅助运行 60 秒，只记录施放次数和冷却节奏，用来验证 TEST-B“内挂只用六格热键、部分职业慢于手动”的玩家报告；不为追求效率使用宏或外部输入。

### 12.2 人工短时运行

只有测试规则允许正常游戏时，由玩家人工启动游戏内功能，并在旁看护 5–10 分钟。记录：

- 启动瞬间；
- 首次选怪／移动／攻击；
- 目标死亡、切换目标；
- 技能冷却和药品；
- 掉落信息；
- 组队成员加入／离开（自然发生时）；
- 无怪／卡位；
- 低血量；
- 玩家人工停止；
- 停止后的结算／面板；
- 加倍分钟和击杀数前后差。

另要验证“弹窗是否暂停”：TEST-B 录像中技能设置、卡片获得遮罩和挂机收益窗出现时，背景战斗可能继续。国服需分别记录打开配置页、普通掉落、卡片遮罩和收益页前后的目标／伤害／击杀变化，不能把窗口出现当作已停止。

不要使用外部工具自动重启、自动吃药或自动恢复。异常只记录和提醒。

## 14. 五人本、十人本、MVP 与竞争玩法

### 14.1 只采人工正常游玩

五人本与十人本由玩家正常参加并完整录屏；研究工具不发送输入。记录：

- 入口卡片、难度、次数、奖励；
- 队伍角色、匹配、确认、取消；
- 入场加载和出生点；
- Boss 名、血条、阶段；
- 地面 AOE 的形状、颜色、动画周期；
- 集合／分散／占位／颜色／节奏提示；
- 玩家死亡、复活、团灭；
- 成功、失败、超时、退出、结算、拍卖。

团队 UI 中其他玩家名称和聊天在提交证据前脱敏。

### 14.2 默认只做排除分类

MVP、PVP、吃鸡、GVG、排行榜和百人玩法只需要采足以识别并触发 `CompetitiveMode`／`MechanicInstance` 停止类的帧。不要围绕它们设计自动操作模板。

## 15. 异常流采样

### 15.1 允许自然收集

当异常自然发生时，立即记下前 30 秒和后 60 秒：

- 断线、重连、服务器繁忙、排队；
- 加载超时、客户端无响应、崩溃；
- 版本更新、维护公告；
- 角色死亡、复活页；
- 通用物品、卡片、灵魂残响等各分类的接近满／真正满、负重、材料不足；不要把某一分类容量外推到其他分类；
- 队长离开、被移出队伍、匹配取消；
- 任务目标消失、寻路停止；
- 游戏内辅助战斗停止、无目标、卡位；
- 加倍结束、疲劳、次数耗尽；
- 协议／反作弊／GM 提示。

### 15.2 不人为制造

不得为采样：故意触发反作弊、刷错误请求、断网骚扰队伍、占用副本、恶意死亡、制造交易失败、发异常聊天或尝试绕过验证。

## 16. 录像与操作日志同步

操作日志每行使用单调递增的会话秒数：

```text
00:03:12.420  MANUAL_CLICK  每日必做入口
00:03:13.105  OBSERVE       页面标题出现“必做”
00:03:18.900  MANUAL_SCROLL 从第一项滚至第三项
00:03:24.010  NOTE          MVP 条目仍锁定，提示 Base Lv.xx
```

日志中的 `MANUAL_*` 明确表示人手操作，不能让后续阅读者误以为脚本已验证。

## 17. 关键帧选取与 Manifest

每个状态从原始录像选最少帧：

- `before`：动作前稳定状态；
- `transition`：只有当过渡会造成误识别时保留；
- `after`：动作后稳定状态；
- `error`：自然出现的错误；
- `recovery`：人工恢复后状态。

文件名：

```text
<session>__<seconds>__<scene>__<state>.png
```

Manifest 必须写：

- 源会话与录像哈希；
- 客户端 build 和环境指纹；
- 精确秒数；
- 画面事实；
- 人工动作；
- 隐私处理；
- 预期场景标签；
- 是否可用于模板训练；
- 下个版本是否需复验。

## 18. 隐私和版权

提交前检查并处理：

- Bilibili 登录信息、手机号、二维码；
- 账号 UID、角色 ID、公会和队友名称；
- 世界／队伍／私聊内容；
- 语音；
- 设备序列号、安装路径中的真实姓名；
- 协议中禁止公开的测试内容。

原始录像不提交 Git。关键帧只为内部研究保留必要范围，并遵守测试协议。

## 19. 样本验收标准

一个页面只有同时满足以下条件，才可进入离线识别开发：

- 至少两个不同会话；
- 至少两个 UI 缩放／分辨率环境，或明确声明首版只支持一个环境；
- 正态、完成态和至少一种不满足条件状态；
- 没有把字幕／水印误当客户端 UI；
- 文本区有可读原生截图；
- 来源、build、时间和哈希完整；
- 已划分训练、验证、回归集合；
- 未知帧上的误触发率达到安全阈值；
- 所有动作相关设计仍保持禁用，除非合规门另行通过。

## 20. 时间有限时的优先顺序

若测试资格或在线时间有限，依次采：

1. 协议、版本和窗口／截图环境；
2. 登录到城镇的完整链路；
3. 操作模式、设置、UI 缩放和恢复默认布局；
4. 常驻 HUD 和所有一级菜单；
5. 每日面板全状态；
6. 任务追踪与一整轮委托；
7. 野外挂机配置页和一次人工短时运行；
8. 背包、死亡、掉线等自然异常；
9. 生活、公会、宠物；
10. 五人本／十人本完整录像；
11. PVP／GVG 仅采排除类页面。

不要为了“多录几个 Boss”牺牲最关键的登录、设置、日常和异常状态。

## 21. 测试结束后的差异审查

把每条旧测试事实标成：

- `CONFIRMED_CN`：国服同构建确认；
- `CHANGED_CN`：名称、位置、次数或规则改变；
- `NOT_AVAILABLE_CN`：本次未开放；
- `UNOBSERVED`：有资格但未采到；
- `BLOCKED_BY_POLICY`：协议不允许采；
- `REMOVED`：官方确认删除。

随后才决定哪些候选进入离线 detector，哪些文档继续保持假设。
