# MAA 候选能力矩阵

> 当前状态：所有真实客户端输入均为 `BLOCKED`。本矩阵用于决定 8 月采什么证据，以及在取得明确书面许可后哪些功能值得进一步设计；它不是上线承诺。

## 1. 评分方法

- `R0`：纯离线研究／资料管理，现在可做。
- `R1`：只读识别或人工提醒；接真实客户端前仍要通过采集许可门。
- `A1`：低影响输入候选；只有专项书面授权后才能进入隔离测试。
- `A2`：复杂或可能影响账号／他人的输入；默认排除首期。
- `X`：本项目永久或长期排除。

技术复杂度使用 `低／中／高／极高`；证据成熟度使用 `充足／部分／不足`。测试视频中的“可做”不等于协议允许。

### 输入候选的共同合同

每个动作必须采用下面的事务，而不是“识别到就点击”：

```text
Intent
  → Policy check
  → Environment + scene precondition
  → One bounded input
  → Observe several fresh frames
  → Verify postcondition
  → Commit journal entry
  → Otherwise stop and save evidence
```

暂停后不能继续旧点击栈；恢复必须重新识别场景并重新生成意图。

## 5. 默认排除或永久排除

| 内容 | 类型 | 原因 |
|---|---|---|
| 自动 MVP 争抢、首刀／尾刀 | A2／X | 直接影响其他玩家与排名，机制和死亡风险高 |
| 五人高难、十人 RAID 自动走机制 | A2／X | 颜色／占位／节奏／集合机制会伤害队友 |
| PVP、吃鸡、排行榜 | X | 竞技公平性 |
| GVG、百人攻城、公会战 | X | 竞争、公会资产、即时指挥和多人责任 |
| 自动组队招募、自动聊天、自动语音 | X | 影响他人并涉及内容与隐私 |
| 自动摆摊、自动定价、扫货、抢购 | X | 经济影响和不可逆交易 |
| 倒金、多账号调度、账号农场、代练 | X | 高风险运营行为，Bilibili 协议明确风险 |
| 自动抽宠、精炼、加点、换装决策 | X | 付费／稀缺资源和不可逆养成 |
| 验证码处理 | X | 不规避人工验证 |
| 随机化／类人化／反检测 | X | 项目不研究规避风控 |
| 注入、读写内存、修改客户端 | X | 永久不采用 |
| 抓包、协议模拟、私有接口 | X | 超出视觉路线且条款有明确限制 |

## 6. 初期价值排序

### 6.1 三个最优先场景的工程把握

百分比表示公开证据对正常链、状态变体和后置条件的覆盖，不代表国服线上实测成功率，也不代表输入已获授权。

| 场景 | TEST-B 固定父场景内 | 国服取得 2–3 个干净会话后的交付预测 | 当前从启动器到完成的广义无人值守 |
|---|---:|---:|---:|
| 已打开每日页：识别＋白名单活跃箱 | 96% | 91% | 68% |
| 已在目标地图：高倍＋官方辅助战斗／内建补药托管 | 91% | 85% | 60% |
| 已在连续可见节点区：五次生活采集＋`100/100` 复核 | 90% | 83% | 57% |

广义分数受登录／连接、任意地图导航、真正满包、药尽、野外死亡和断线恢复拖累；不能用窄流程高分替代整机零接管承诺。

如果 8 月后仍没有线上输入授权，项目仍有可交付价值：

1. 每日与活动状态看板；
2. 挂机／掉线／死亡／背包满等人工提醒；
3. 操作清单和一键记录当前完成情况；
4. 离线录像回放、模板维护和版本差异报告；
5. 为官方共创或书面授权测试准备完整、可审计的验证框架。

这比先写一套坐标点击脚本更适合当前信息量，也能在国服 UI 变化后保留大部分工程资产。
