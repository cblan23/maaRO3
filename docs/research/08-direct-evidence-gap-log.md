# RO3 流程级直接证据与负向检索记录

> 状态快照：2026-07-28（Asia/Shanghai）。本文件只回答“现有公开资料是否已经连续拍到目标流程”。`TEST-B` 的闭环只能关闭旧测试的存在性问题，不能替代国服 `CN-A` 同 build 复验。

## 1. 直接证据判定标准

一条流程只有同时具备以下内容，才标记为直接：

1. 同一来源、同一构建、可排序的连续时间点；
2. 动作前的页面、资源或业务状态；
3. 玩家或游戏内功能执行动作；
4. 动作后的进度、资源、奖励或持久状态变化；
5. 来源、时间戳、限制和 SHA-256 均写入 Manifest。

聊天、标题、解说、搜索摘要、其他 RO 产品、单独入口和剪辑后的成功页都只能定位候选。Twitch 聊天命中必须回抽视频；论坛静态原图必须使用 Still Manifest，不能伪造 `0 秒视频帧`。

## 3. 本轮新关闭或显著缩小的缺口

### 3.1 活跃箱：可领与已领已经分开

[VOD 2807782689 Manifest](../../research/evidence/video/twitch-vod-2807782689/manifest.json)以 0.1 秒级回抽保存：

```text
13:35.2  活跃度 20，20 档为金色发光可领
13:35.6  输入后仍为金色，属于过渡状态
13:37.0  持久绿色勾选，并出现奖励反馈
```

这证明点击本身不是成功判据，也纠正了早期单帧绿色勾选无法区分“可领／已领”的问题。其他阈值是否完全复用外观仍需逐档采样。

### 3.2 公会商队：不是“只有入口”

[VOD 2805645541 Manifest](../../research/evidence/video/twitch-vod-2805645541/manifest.json)保存 8 帧，其中连续业务链为：

```text
装运商队 1/4
→ 煤矿石需求／库存 6/6，载货 7/8
→ 玩家装载
→ 物品已提交，载货 8/8

→ 恭喜获得奖励层
→ 装运商队 2/4，新需求同时含满足与不足项目
```

因此“需求选择、正常提交、满载奖励和下一批”已有直接证据。新增[第四批三帧](../../research/evidence/video/test-b-long-review-bv1rrmw6qeom/manifest.json)先直接显示“装运商队 `4/4`”，随后在同一短片段记录 `50.75s` 载货量 `4/8`、发车禁用及至少达到 5 的提示，再于 `51.50s` 记录第五项变绿、载货量 `5/8` 和黄色“发车”按钮启用。它把批次字典与本次发车视觉边界补成直接证据，但没有连续第三批，也没有点击发车。仍不能声称：煤矿石精确扣除 6 个、全部四批都相同、发车确认／最终奖励如何呈现、每日条目随后如何变化，或库存不足时应一键购买／求助；`5/8` 更不是自动发车授权。

`2/4` 新批次父帧还直接包含铁矿石 `0/6` 等库存不足行，以及“求助”“一键购买”入口；现已保存独立 `0/6` 裁图。它只关闭“不足如何显示”的存在性缺口，没有录到选择不足项、按钮禁用／失败、购买价格、求助副作用或返回路径。

### 3.3 生活任务：实际不是 `4/5 → 5/5`

[生活采矿 Manifest](../../research/evidence/video/life-mining-bv18h756kehz/manifest.json)现有 9 帧：

| 次序 | 活力 | 矿工经验 |
|---:|---:|---:|
| 基线 | 700 | 0 |
| 第 1 次 | 680 | 220 |
| 第 2 次 | 660 | 440 |
| 第 3 次 | 640 | 660 |
| 第 4 次 | 620 | 880 |
| 第 5 次 | 600 | 1100 |

每次都有 4.5 秒采集进度和资源／掉落反馈。约两分钟后同一实机重新打开每日页，明确显示“生活玩法：消耗活力值 `100/100`、已完成”。旧日志把任务写成次数 `4/5 → 5/5` 是错误模型；正确的 TEST-B 文本是累计活力值。缺口只剩即时 `80/100 → 100/100` 和异常分支，而非“是否完成”。

同一巴哈姆特原始视频的另一条已登记转载又对生活窗口按 0.1 秒重审，形成[配方制作六帧链](../../research/evidence/video/life-crafting-bv1d67v6pemq/manifest.json)：绿色药水选中但锁定 → “学习”确认框及 1000 道具 → “配方解锁／厨师／绿色药水”成功层 → 同坐标药水图标与金色“制作”按钮 → 指针位于制作按钮 → 0.1 秒后提示“所需消耗的道具不足，无法制造！”。前后活力均为 `700/5000`，远高于可见单次消耗 `20`，因此这条可以直接关闭“是否存在材料不足反馈”的缺口，但不能关闭具体缺料、真正制作成功、批量、活力不足或满包。金色按钮仍允许进入失败分支，自动化不能用颜色替代材料与业务结果校验。

### 3.4 成长徽章：领取、行重排和已完成已闭环

[成长徽章 Manifest](../../research/evidence/video/growth-badge-bv1d67v6pemq/manifest.json)把同一任务收紧到原生帧：`1121.754s`“天赋总等级达到120级”为 `126/120`、金色“领取”，左侧晋升任务 `1/7`；`1121.787s` 原行已移除、列表上移，左侧变 `2/7`，原坐标被“打造6件3阶装备 `1/6`／前往”占用；稍后下滚，同标题和同奖励图标显示 `120/120／已完成`。六张裁图还保存开放世界入口“成长徽章／可领取”。

这关闭了单任务“可领是否能和完成分开”“领取后是否有稳定页面变化”的缺口，并证明成功后旧坐标会立刻复用。仍不能声称奖励已精确到账：没有 toast 或背包账本，入口可领取在领取一条后仍保留；客户端字面也是“已完成”而非“已领取”。`126/120→120/120`只按完成态封顶候选处理，不解释为属性下降。仍缺整阶段 `7/7`、晋升、领取失败、背包满和国服状态。

### 3.5 高倍挂机：可用、运行、耗尽均已保存

- [可开启](../../research/evidence/video/twitch-vod-2805739995/frames/5895.00-farming-boost-available-clean.jpg)：`60分/180分`，金色开启按钮；

## 4. 仍未关闭的高风险流程

### 4.1 呆呆委托整轮

已知每日页有入口，玩家一手文称流程依赖游戏内寻路并可能跨多个跑腿／打怪目标。没有连续录像覆盖：

```text
每日页前往 → 接取 → 至少两类子目标 → 跨图／对话／战斗
→ 最后一环 → 交付 → 每日完成／活跃变化
```

因此只能维护 `Navigating / Interacting / ObjectiveAdvanced / Blocked / Unknown` 采样标签，不得生成真实循环次数。

### 4.2 低倍与疲劳

Day1 图文称一般阶段无装备／卡，Day2 解说称低倍仍有基础装备、材料和卡片，疲劳后才无卡。謝財財在自己 `BV19HTn6PEo2` 下的作者回复又明确写成“健康＝正常收益、没有健康＝降低收益、疲劳＝等同没收益”（`rpid=307490554561`，2026-07-25）；这是可定位的一手作者文字，但不是客户端运行时画面。`2804807809` 的连续帧现在直接证明高倍为零时奖励通知仍会新增经验、齿轮和物品，因此“归零后绝对没有任何奖励”不再成立；但公开画面仍没有同一账号、同一怪物、同一队伍跨过：

```text
高倍剩余 > 0 → 高倍 = 0 → 低倍稳定态
→ 击杀阈值 → 疲劳稳定态 → 掉落资格变化
```

高倍耗尽和耗尽时奖励活动已经直接出现，但“低倍”的客户端名称、相对掉率／卡片资格以及疲劳转换仍是冲突口述。实现必须允许 `UnknownRewardTier`。

### 4.3 真正满包

`0/300` 与 `36/300`只建立 OCR 和正常视觉基准。仍缺：接近满、真正满、下一次掉落、邮件／临时包、卡片去向、扩容与仓库满。不得为了采样故意丢弃稀有物或购买扩容。

困难副本样本证明 `DungeonDeadWait / ReviveInvite / PartyWipe / RetryVote` 彼此不同，但不能外推开放世界。Twitch 聊天中的“死了”“自动复活”均已回抽为误命中或没有对应画面。

```text

→ BattlefieldSpectate8 @ 82.00
→ RevivePointWait5 @ 85.25
→ RevivePointWait2 @ 88.00
→ CountdownZeroStillDead @ 90.00

```

约 `229–238s` 还出现第二轮同类循环。`0 秒`与技能栏恢复不是同一帧，因此检测器必须等待可操作 HUD，而不是只看数值归零。该录像属于 PIONEER-A 模拟对抗赛，不能关闭 TEST-B／国服开放世界页面、选项、费用、惩罚、复活落点或 AutoOn 保留。另一条 [PIONEER-A 公会战](https://www.bilibili.com/video/BV1WGbhz2EMB/)已全程按 2 秒复核，红／绿区域变化均没有形成可靠玩家死亡 UI，作为负向来源登记。野外死亡缺口仍未关闭。

五个重点主题的原图只覆盖宠物／精炼／商城、一般战斗、主线对话、角色外观和座谈照片；没有接近满载读数、疲劳状态、真正满包、野外死亡、公会四批终局或生活异常。因此零张复制进正式证据目录。

本地已登记的 87 条 Bilibili 视频评论／弹幕又使用扩展同义词复扫。除 `BV1ptaZzwE6C` 下作者“死了也没事可以原地复活”的旧构建评论外没有新线索；该录像本身没有玩家死亡画面，评论仍只作候选语义，不能成为复活证据。Bilibili 新一轮标题／摘要检索中的“活力不足、背包已满、安全复活”等大多是推荐误命中；`BV1wJTb6BEdY` 已按 2 秒全片审完，精确文案命中的 `BV1w9736mETV` 也按 0.5 秒全片确认是经典 RO，二者均作为负向来源登记。材料不足证据不是由关键词命中得到，而是对已审长实机的生活窗口做亚秒回抽后发现；这也说明二秒故事板适合排除大场景，却不足以否定短暂 toast、确认框和动画覆盖层。

## 7. 资产与负向结果口径

当前机器可读资产经校验为：

```text
259 条来源
36 份视频 Manifest / 166 张视频关键帧
1 份静态 Manifest / 1 张论坛一手原图
121 张正式裁图 / 64 个图标与状态键
```

故事板、聊天命中、被排除的网页、宣传混剪和误判帧不计入关键帧数量。只有已复制到证据目录、写入 Manifest、校验哈希且直接支持限定事实的图片才叫“已保存证据”。

## 8. 国服最小补证序列

| 流程 | 必须连续录到的最短序列 |
|---|---|
| 呆呆 | 每日条目 → 前往 → 接取 → 至少两类子目标 → 最后一环 → 交付 → 完成／活跃变化 |
| 成长徽章剩余分支 | 以现有 `领取 → 行移除／1/7→2/7 → 已完成`作正常链；补奖励到账、入口可领取清空、整阶段 `7/7` → 晋升、领取失败与背包满，客户端字面状态分别记录而不混成通用“已领” |
| 公会商队剩余分支 | 已知 `0/6` 不足行 → 人工选择后记录装载按钮／失败反馈 → 查看来源／购买／求助入口（不执行）→ 背包前值 → 人工提交普通材料 → 背包后值 → 已知 `5/8` 发车可用后的人工点击、确认／成功／失败 → 第四批终局 → 每日变化 |
| 生活异常 | 采集：`80/100` → 第五节点 → `100/100`，自然记录节点被抢／消失、活力不足和满包；制作：以已知材料不足作负例，补材料足够 → 人工制作 → 材料／活力／产物／熟练度账本，另补批量、活力不足和满包 |
| 挂机阶段 | 同账号高倍倒计时 → 归零（现已知奖励通知仍活动）→ 客户端低倍标签／同怪相对掉率 → 击杀阈值 → 疲劳 UI／同怪掉落变化 |
| 真正满包 | 容量接近满 → 正常拾取 → 真正满 → 下一掉落去向 → 清理前停机 |
| 药尽 | 已启用自动用药 → 数量 `1 → 0` → 低血量 → 原生提示／行为 → 玩家接管 |
| 野外死亡 | HP 归零前 → 死亡页 → 全部选项／费用 → 玩家手动选择 → 复活落点与 Auto 状态 |
| 连接剩余分支 | 现有 TEST-B 页面链作为采样种子；国服连续记录冷启动／更新 → 账号认证 → 公告 → 服务器／排队／维护 → 角色页 → 加载 → 世界，并补角色创建／删除／多角色边界；自然掉线时额外保留输入事件、开放世界落点与 Auto／任务状态前后值 |
| 国服视觉矩阵 | 每个相关控件的普通／悬停／按下／选中／锁定／可领／已领／禁用；不存在者标 `not_applicable` |

在这些高风险分支和国服状态补齐前，固定场景内的窄流程可以做离线状态机，广义“从启动器到完成并自动恢复”的无人值守脚本仍不能宣称完成。
