# RO3 × MAA 预研总档案：长期设计依据

> 知识快照：2026-07-28。目标产品仅指 Bilibili 独家代理的中国大陆国服《仙境传说3》（以下简称 `CN-A`）。2026-06-25 至 07-02 台港澳“启燃测试”属于同项目旧构建 `TEST-B`，只提供结构旁证。本文不是国服正式攻略，也不把《爱如初见》《新启航》《守护永恒的爱》《世界之旅》或原版 RO 的规则移植过来。

这份文件是以后做需求、识别、状态机和测试设计时的第一入口。细节必须继续回到[玩法事实库](01-game-facts.md)、[日常系统百科](07-daily-system-encyclopedia.md)、[直接证据缺口](08-direct-evidence-gap-log.md)、[UI 证据索引](03-ui-evidence-index.md)及各视频 `manifest.json`，不能只引用本文摘要。

## 1. 目前最重要的结论

### 1.1 RO3 是什么类型

RO3 是持续在线、开放世界、带社交与长期养成的 MMORPG，不是 MaaKES 那种“选关 → 固定地图操作 → 结算 → 返回”的封闭关卡游戏。角色会长期停留在城镇、开放地图、任务追踪、队伍、活动和多个可重排窗口组成的环境中；任务、系统开放、日常条目和资源都会随角色等级、服务器时间、队伍、构建版本与运营活动变化。

这决定了 MAA 设计不能以固定坐标脚本为核心。更合适的模型是：

```text
玩家设定意图与预算
  → 游戏自身执行寻路／辅助战斗
  → MAA 只读观察业务进展与安全状态
  → 正常完成则报告；异常或未知则停止并提醒人工
```

### 1.2 RO3 是否有自动战斗／挂机

需要分三层回答：

1. `TEST-B` 直接画面确认存在游戏内建自动战斗、技能设置窗、自动选怪／切换目标、野外挂机选择页、加倍分钟和挂机收益统计。
2. 全球／台港澳制作人采访明确介绍“辅助战斗”，称设计目标是辅助收益低于手动，约为手动的 70%～80%；这是产品设计说明，不是国服数值保证。
3. `CN-A` 国服官方首曝片使用了简体中文开放世界 HUD 素材，但没有给出 8 月客户端 build，也没有完整展示自动战斗规则页。因此，严谨结论是：**同项目最新公开测试支持官方自动战斗和挂机；2026-08-27 国服重逢测试是否原样开放、何时解锁、如何配置，仍必须实机复验。**

“游戏自己有内挂”不代表外部程序获准模拟键鼠。Bilibili 通用协议当前已限制模拟用户操作和自动任务；专项书面许可缺失时，本仓库只做公开资料与离线研究。

### 1.3 MAA 最值得帮玩家做什么

用户已经排除副本、MVP、PVP、GVG 等战斗／竞争玩法。结合现有证据，最高价值不是重写战斗 AI，而是减少遗漏、重复检查和挂机看护负担：

- 读取每日／周常面板，生成未完成、已完成、可领奖和锁定原因清单；
- 读取活跃度和阶段箱，只提醒安全可领奖项；
- 对照玩家预先配置的快捷栏与官方自动战斗设置，报告漏配、禁用和职业差异风险；
- 观察官方自动寻路／自动战斗是否持续产生业务进展；
- 识别卡位、长期无目标、死亡、低血量、药尽、满包、掉线、维护、加倍结束和疲劳等状态；
- 读取生活职业、活力、熟练度、配方与单次资源预算；
- 读取公会物资需求和库存缺口，不自动购买或提交；
- 读取魔物图鉴／讨伐阶段和可领奖状态，不以最高长期目标驱动无限打怪；
- 读取活动日历并按服务器时间提醒；
- 保存带版本、环境、时间和截图的日报／异常证据包。

搜索结果中最常混入：

## 3. PC 操作与 UI 事实

### 3.1 操作模式

`TEST-B` 画面显示三种候选模式：

- 经典：鼠标左键点地移动；
- 现代：WASD 移动，鼠标参与朝向／交互；
- 行动／手机：旧测试有入口，当时可用性不完整。

旧测试攻略称 `Z` 曾是自动战斗开关，右键可进入技能设置。它们都是易变字段；国服必须人工打开键位设置逐项确认，不能从视频字幕直接生成输入。

### 3.2 UI 不是固定主页

制作人说明 PC 窗口可拖动、缩放，聊天框可自由摆放；旧测试还可调整 UI 缩放。常见 HUD 虽包括头像、Base／Job、HP／SP、队伍、聊天、技能栏、小地图、任务追踪和菜单，但这些区域会随布局、分辨率、DPI、队伍和玩法变化。

识别的前置字段必须包括：

```text
client_build / channel / language
window_client_size / dpi / display_scale
render_resolution / display_mode / ui_scale
control_mode / layout_fingerprint
```

没有匹配的环境指纹时，系统应返回 `UnsupportedLayout`，不能退化成模糊坐标点击。

### 3.3 弹窗不等于暂停

连续挂机录像已出现以下情况：

- 自动战斗设置窗打开时，背景战斗继续；
- 卡片大遮罩出现时，背景仍可能继续攻击；
- 挂机收益窗口打开时，后台战斗可能继续。

因此页面分类与战斗运行状态是两个正交维度：

```text
Overlay = None | Settings | CardDrop | FarmSummary | Reward | Unknown
Combat = Off | Starting | Moving | Fighting | NoProgress | Stopped | Unknown
```

不能因为出现模态视觉就假设角色安全，也不能用“面板已打开”作为停止成功判据。

## 4. 官方自动系统的边界

### 4.1 自动寻路／任务追踪

公开视频普遍通过右侧任务追踪触发游戏自身寻路、跨图或继续对话。仍未知：

- 玩家手动移动后是否打断；
- 跨图加载后是否恢复；
- NPC 被遮挡、目标消失、路线失败时的提示；
- 到达后是自动对话、自动战斗还是等待人工；
- 最终交付与下一环是否自动发生。

MAA 价值是识别 `Navigating / Loading / Arrived / Interacting / Fighting / ObjectiveAdvanced / Blocked`，而不是计算世界坐标路径。

### 4.2 自动战斗配置

TEST-B 设置窗直接显示技能类别、技能和等级。一名玩家报告：当时内挂只施放六格热键栏中的技能、战斗中不能换栏，猎人内挂施放可能慢于手动。这个报告只适用于该玩家、该职业和该构建，不能成为通用规则。

国服需对至少一个普攻职业、施法职业和猎人分别人工验证：

- 热键栏与自动技能页映射；
- 启用／禁用项；
- 技能优先级与冷却；
- 索敌范围、追击和返回原点；
- HP／SP 药品是否另有设置；
- 战斗中换栏、传送、死亡、断线后的状态；
- 手动与辅助 60 秒的施放节奏差异。

### 4.3 野外挂机面板

旧构建可见地图／等级区间、魔物列表、单目标选择、加倍剩余分钟、累计上限、规则、组队说明和开始入口。挂机和自动战斗可能是相互关联但不同的页面／状态，不能把 `Z`、挂机开始按钮和加倍开关当成同一个 toggle。

旧资料支持至少三种收益候选：

| 阶段 | 已知 | 冲突／未知 |
|---|---|---|
| 加倍／高倍 | TEST-B 曾显示每日 60 分钟、可累计 180；有经验、装备、卡片 | 国服名称、分钟、累计、是否按现实时间消耗 |
| 低倍／一般 | Day2 称仍可掉基础装备、材料和卡；Day1 称一般阶段无装备卡；新增连续帧证明 `0秒/180分` 时经验、齿轮和物品通知仍在变化 | 客户端没有显示“低倍”标签，物品集合与掉率仍冲突，禁止据此命名阶段或硬编码 |
| 疲劳 | 多名玩家称按击杀数而非时间；Day2 称疲劳后无卡片；另一名玩家称角色疲劳后“几乎没有任何收益” | “几乎没有”仍是体验口述，不等于零收益；阈值、队友击杀归属、经验／材料限制和稳定 HUD 标志均未知 |

未拍到“加倍归零 → 低倍 → 疲劳”的同怪、同队伍连续边界前，数据字段必须允许 `UnknownRewardTier`。

公开长直播已经把高倍本身补成三个可区分页面状态：[可开启 `60分/180分`](../../research/evidence/video/twitch-vod-2805739995/frames/5895.00-farming-boost-available-clean.jpg)、[运行中 `59分40秒/180分`](../../research/evidence/video/twitch-vod-2804892798/frames/11140.00-farming-boost-active-countdown-later.jpg)和[耗尽 `0秒/180分`](../../research/evidence/video/twitch-vod-2804807809/frames/24411.00-farming-boost-exhausted.jpg)。运行态在同一直播中十秒递减十秒；耗尽提示相隔约 24 秒仍稳定，并写有次日 05:00 补充。耗尽页保持打开期间，[奖励通知](../../research/evidence/video/twitch-vod-2804807809/frames/24420.00-farming-boost-exhausted-reward-feed.jpg)从 `Base经验 X3` 继续变化为齿轮、经验和`连帽披肩 X1`，同时可见背景伤害；因此“高倍归零会自动停战或必然完全零收益”已被直接排除。可开启、运行和耗尽仍来自不同账号，不能伪装成同账号连续转换；画面也没有“低倍”或“疲劳”标签，真正仍缺的是阶段命名、掉率／资格及疲劳边界。

### 4.4 卡位异常已经出现，但证据仍不完整

[14 秒 TEST-B 序列](../../research/evidence/video/auto-blocked-terrain-bv1rg376ue6k/manifest.json)中，角色在狭窄走廊边缘约 13 秒没有有效位置进展，但动作轨迹、伤害数字和周围魔物仍变化；作者标题称近战自动挂机被地形卡住反复左右。

可确认：画面没有冻结，单看“有动画／有伤害”会误判为健康。不能确认：清晰 AutoOn 标志、选中目标、碰撞点、击杀是否停滞、是否自行恢复、所有近战职业是否复现。

因此卡位检测需要滑动时间窗和组合信号：

```text
position_progress ≈ 0
AND objective_progress ≈ 0
AND animation_or_damage_changed = true
AND target_or_navigation_intent_expected = true
FOR configurable_observation_window
→ AutoOnBlockedCandidate
```

输出只能是保存证据和提醒人工；不能自动按 `Z`、随机走动或重新选怪。

### 5.1 呆呆委托的待验证状态机

当前只能建立采样标签：

```text
ErrandEntry
→ NavigatingToIssuer
→ AwaitingAccept
→ NavigatingToObjective
→ Interacting | Fighting | Gathering
→ ObjectiveAdvanced
→ AwaitingTurnIn
→ NextObjective | ErrandComplete
```

任何时候都可能进入：

```text
ErrandBlocked / ErrandUnknown / Loading / DialogueChoice / InventoryBlocked
```

缺失：接取、至少两类目标、最后一环、交付、每日进度与活跃变化的同一连续录像。未补齐前，不能把玩家所说“五个地点、往返约十趟”或任何环数当作状态机循环次数。

### 5.2 公会物资：单批装载与第四批发车边界已经直接出现

一份玩家系统概观称多数测试需求可在普通补给商店用一般游戏币购买；另两名玩家称公会商队会要求生活职业产物。两者可能都成立，只是需求池、日期或公会状态不同。现在另有同一直播的连续直接证据：煤矿石候选显示 `6/6`，载货量 `7/8`；装载后 0.2 秒出现“物品已提交”并变为 `8/8`；随后出现公会贡献与钱币提示、奖励覆盖层，页面刷新为“装运商队 2/4”和一组新需求。完整序列见 [Twitch VOD 2805645541 Manifest](../../research/evidence/video/twitch-vod-2805645541/manifest.json)。

这关闭了“是否存在需求选择、装载反馈、满载奖励和下一批”的存在性缺口，但没有显示提交后的背包数量，连续链也只覆盖第一批到第二批。另一条二次剪辑的[三张直接父帧](../../research/evidence/video/test-b-long-review-bv1rrmw6qeom/manifest.json)清楚显示“装运商队 `4/4`”进行中：`50.75s` 载货量为 `4/8`，发车区域为深色禁用态并提示至少达到 5；`51.50s` 已有第五项绿色装载，载货量为 `5/8`，黄色“发车”按钮启用。这把第四批的发车视觉边界补成同一短片段内的直接变化，但视频没有点击发车。因此不能把材料扣除数量、点击发车后的确认／奖励、全部四批完成、每日条目变化或一键购买写成已确认规则，也不能把识别到 `5/8` 当作自动发车授权。

必须连续七天记录：

```text
requirement_item / quality / required_count
owned_count / locked / bound / rarity
source_type / ordinary_currency_shop / life_product / unknown
submit_preview / confirmation / inventory_delta
guild_fund_delta / task_progress / active_points
```

库存不足跳转商城时只记录页面。任何货币购买、稀有材料选择或提交都由玩家人工确认。

### 5.3 生活采集已经证明什么

连续实机基线：

```text
Miner Lv1 0/5000, Vitality 700/5000
→ Level-1 Ore Node
→ Pickaxe interaction
→ GatheringProgress 0..4.5s
→ Pickup log
→ Vitality -20, MinerExp +220
```

连续五次后观察到活力 `700 → 600`、矿工经验 `0 → 1100`，证明五个节点事务实际发生。同一条实机约两分钟后重新打开每日页，生活玩法明确显示“消耗活力值 `100/100`、已完成”，因此五次累计消耗与稳定完成态已经闭环。旧文档曾要求寻找 `4/5 → 5/5`，这是错误的数据模型：该任务按活力值显示 `0/100 → 100/100`，不是按次数显示 `0/5 → 5/5`。仍缺的是即时 `80/100 → 第五次 → 100/100`、活跃度单项增量，以及节点被抢、中断、活力不足和满包分支。

## 8. 未来动作的事务合同

如果将来取得明确书面许可，任何一次输入仍必须是有界事务：

```text
Intent
→ Authorization + policy check
→ Build + environment fingerprint check
→ Scene + resource + safety precondition
→ Exactly one bounded input
→ Wait for fresh frames
→ Verify business postcondition
→ Commit journal entry

禁止：识别到模板就连续点击、暂停后恢复旧点击栈、未知状态盲按 toggle、失败后无限重试、用随机移动“解卡”。

每个事务至少记录：

authorization_id:
run_spec_hash:
before_scene:
before_resources:
action_budget:
input_sent:
after_scene:
postcondition:
result:
evidence_refs: []
started_at:
finished_at:
```

## 11. 进入实现前的门槛

一个页面只有满足以下条件才进入离线识别开发：

- 明确国服 build、渠道和环境指纹；
- 至少两个独立会话；
- 正态、完成态和相邻混淆态；
- 至少覆盖一个 UI 缩放／分辨率的明确支持档；
- 原生文本可读，不把字幕、水印和主播覆盖当 UI；
- 训练与验证样本隔离；
- 未知帧不会触发输入意图；
- 版本更新后默认回到 `needs_recheck`。

一个任务只有满足以下条件才进入事务设计：

- 入口、前置、动作、进行态、成功态、失败态都有证据；
- 资源消耗与不可逆影响已列出；
- 完成判据是业务变化而非页面变化；
- 所有相邻危险页面都有停止规则；
- 对应行为有明确专项书面许可；
- 有动作次数、时长和失败预算；
- 能在本地回放与隔离环境验证。
